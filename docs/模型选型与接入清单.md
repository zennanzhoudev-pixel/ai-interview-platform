# 模型选型与核心链路接入清单

本文档回答三件事, 并且**只描述当前代码的真实状态**, 不写"将来要怎么做"的愿望。

1. 接哪些模型、推荐哪家、怎么充值;
2. 核心链路里"已接 / 半接 / 没接"逐项标注, 以及每项缺什么测试、缺什么数据;
3. 设计规范(避免魔数、配置统一)与"尚未接入"的显式声明。

## 一、模型选型(国内可用、无需翻墙、充值方便)

系统里有四类模型能力, 按重要度排序:

| 能力 | 作用 | 没接时的表现 |
|---|---|---|
| LLM(大脑) | 追问、评分、生成报告依据 | 回落到关键词规则评分, 报告会标注"规则评分" |
| ASR(耳朵) | 把候选人语音转成文字 | 语音模式不可用 |
| TTS(嘴巴) | 把 AI 的话念出来 | 语音模式不可用 |
| Embedding(检索) | 语义召回 | 回落到本地特征哈希(词面相似度) |

**核心结论: 最该先接的是 LLM**, 其次才是 ASR/TTS。因为即使不开口(文字面试),
追问和评分也已经需要 LLM; ASR/TTS 只有"语音模式"才需要。

### 推荐方案: 一家包圆, 减少账号与充值成本

首选 **火山引擎(豆包)**, 理由: 中文强、价格低、有免费额度、四类能力齐全,
并且都提供 **OpenAI 兼容接口** —— 这意味着本项目几乎零改动就能接入
(代码里本来就是按 OpenAI 兼容协议写的)。

| 能力 | 豆包(火山引擎) | 阿里云百炼(DashScope) |
|---|---|---|
| LLM | doubao-pro / doubao-lite | 通义千问 qwen-max / qwen-plus |
| ASR | 大模型流式语音识别 | Paraformer 实时语音识别 |
| TTS | 音色合成 | CosyVoice |
| Embedding | doubao-embedding | text-embedding-v3 |
| OpenAI 兼容 | 支持 | 支持(兼容模式) |
| 充值 | 火山引擎账户(个人/企业实名) | 支付宝/阿里云账户 |
| 免费额度 | 新用户有赠送 | 新用户有赠送 |

二选一即可, 建议从豆包开始。若只想单独换 LLM, DeepSeek 是最便宜的选择之一,
但它没有 ASR/TTS, 所以只能当"大脑", 耳朵嘴巴还得另接。

### 成本量级(测试用)

一场 45 分钟语音面试: ASR 约 1–2 元, TTS 约 1 元, LLM 约 0.1–0.5 元。
**测通开发全流程, 几家新用户免费额度通常就够, 基本不用自掏钱。**

### 接入所需的环境变量(现状已支持, 不用改代码)

```bash
LLM_BASE_URL=...      # 例如 https://ark.cn-beijing.volces.com/api/v3
LLM_API_KEY=...
LLM_MODEL=doubao-pro-32k
LLM_MODEL_B=...       # 可选: 复核模型, 启用双模型交叉评分

ASR_BASE_URL=...
ASR_API_KEY=...
ASR_MODEL=...

TTS_BASE_URL=...
TTS_API_KEY=...
TTS_MODEL=...

EMBEDDING_BASE_URL=...
EMBEDDING_API_KEY=...
EMBEDDING_MODEL=...
```

配置后先跑一次联调自检, 别让第一场面试替你做冒烟:

```bash
make selftest
```

## 三、设计规范(避免魔数与模糊)

1. **所有地址/密钥/模型名/阈值都走环境变量**, 命名统一大写蛇形
   (如 `LLM_API_KEY` / `FACE_THRESHOLD`), 不在代码里写死。
2. **阈值必须跟着模型走**(人脸阈值就是典型例子): 本地匹配器 0.95,
   真实模型 0.60, 换模型会自动换默认值, 也可显式覆盖。
3. **降级必须可见**: 没配大模型就明确在报告与日志里标注"规则评分",
   绝不静默假装用了模型。
4. 少量**安全/协议常量**当前仍写死在代码里, 且**刻意不开放配置**
   (它们是边界不是调优项): PBKDF2 迭代次数(21 万)、WebSocket 心跳与超时、
   VAD 阈值、判题沙箱资源上限。需要放开时单独说明理由, 不顺手放开。
