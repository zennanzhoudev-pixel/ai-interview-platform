# 开发指南

## 环境要求

| 依赖 | 版本 | 是否必需 |
|---|---|---|
| Go | 1.22+ | 必需 |
| Node.js | 22+ | 仅前端静态检查需要 |
| Docker | 任意近期版本 | 运行 MySQL/Redis 与判题沙箱需要 |
| MySQL | 8.0 | 可选 (不配则用内存) |
| Redis | 7 | 可选 (不配则单实例内存) |

## 快速开始

```bash
# 零依赖跑一场完整面试并输出报告
make run

# 起服务 (前台, 8080)
make serve

# 起服务 (后台常驻, 8101)
make up

# 联调自检: 探测 LLM / Embedding / TTS
make selftest
```

服务启动时会自动读取项目根目录的 `.env` (已在 `.gitignore` 中)。
已存在的环境变量优先, 便于临时覆盖。

## 扩展点

项目刻意把「能力」与「实现」分离, 换厂商只需要新增一个实现。

| 想扩展 | 实现接口 | 位置 |
|---|---|---|
| 新的大模型协议 | `llm.Client` + `APIMode` | `internal/llm` |
| 新的 ASR 厂商 | `media.ASRProvider` | `internal/media` |
| 新的 TTS 厂商 | `media.TTSProvider` | `internal/media` |
| 新的 Embedding | `rag.Embedder` | `internal/rag` |
| 新的人脸模型 | `account.Matcher` | `internal/account` |
| 新的追问方向策略 | `orchestrator.ProbePlanner` | `internal/orchestrator` |
| 新的追问措辞 | `orchestrator.FollowUpPhraser` | `internal/orchestrator` |
| 新的评分器 | `scoring.Scorer` | `internal/scoring` |
| 新的通知通道 | `account.Notifier` | `internal/account` |

接入示例 (ASR):

```go
type MyASR struct{ APIKey string }

func (p *MyASR) Name() string { return "my-asr" }
func (p *MyASR) Open(ctx context.Context, cfg media.ASRConfig) (media.ASRStream, error) { ... }
```

然后在 `buildASRProvider` 中按环境变量选择实现即可。

## 新增题目 / 阶段

- 题目与参考要点是同一条数据: 改题库时同时更新 `reference points`,
  否则追问的依据会和实际问的题对不上。
- 阶段由 `orchestrator.Plan` 定义; 新增阶段要同时补:
  阶段规格、题库覆盖、预算策略、报告维度。

## 编码约定

1. **所有地址/密钥/模型名/阈值走环境变量**, 不写死。
2. **降级必须可见**: 缺少模型时明确标注"规则评分 / 词面相似度 / 本机执行"。
3. **失败不静默**: 语音未配置时明确拒绝, 不假装成功。
4. **金额/时长/阈值跟上实现**: 修改行为时同步更新文档与测试。
5. **并发安全**: 共享状态加锁, goroutine 用 `safeGo` 兜底 panic。

## 常见坑

- **前端编在二进制里**: 改 `web/` 后必须 `make build` + 重启, 浏览器硬刷新。
- **端口被占**: `make down` 后再 `make up`; 用 `make status` 确认。
- **配置丢失**: 终端 `export` 只对当前会话有效; 写进 `.env` 才持久。
- **go:embed**: `web/embed.go` 显式列出资源, 新增文件要加进 embed 列表。
- **沙箱环境**: 绑定端口/启动容器可能被限制, 这属于环境问题而非代码问题。
