# 测试与质量

本项目把测试分成五层, 每层的目标是「在没有外部依赖时也能给出确定结论」。

## 1. 单元测试 (无外部依赖)

覆盖评分、编排、检索、VAD、密码学、账号规则等纯逻辑。

```bash
make test            # go test ./... -count=1
make test-race       # 带竞态检测
```

## 2. 契约测试 (内存 / MySQL 同一套用例)

同一组用例同时跑内存与 MySQL 实现, 保证两者行为一致:

```bash
make test-mysql      # 需要 docker compose up -d mysql
```

不在 CI 之外的机器上默认跳过; 跳过不会让测试变绿, 而是明确 `SKIP`。

## 3. 真实模型集成测试 (有密钥才跑)

| 测试 | 环境变量 | 验证内容 |
|---|---|---|
| `TestLLMScorerAgainstRealModel` | `LLM_API_KEY` | 真实模型能产出有效评分 |
| `TestLLMFollowUpPhraserAgainstRealModel` | `LLM_API_KEY` | 追问自然且锚定参考答案 |
| `TestDoubaoTTSAndASRRoundTrip` | `DOUBAO_API_KEY` | TTS 合成 → ASR 识别闭环 |

没有密钥时 `t.Skip`, 不会让 CI 因为缺外部依赖而红。

## 4. 端到端离线模拟

不接任何外部服务, 跑完整场面试 (提问 → 追问 → 评分 → 报告):

```bash
make run
```

CI 中也会执行一次并校验报告文件非空。

## 5. 真实链路延迟测量

```bash
go run ./cmd/latencybench
```

实测参考 (本机, 2026-11-19):

| 链路 | 延迟 |
|---|---|
| LLM 单次调用 | ~1.2s |
| TTS 首块 | ~1.3s |
| TTS 整句合成 | ~1.6s |
| ASR 收尾 (最后音频 → final) | ~3.3s |

## 前端检查

前端没有构建步骤, 因此用静态检查兜底:

```bash
make frontend-check
```

- ES 模块语法 (`node --check`)
- JS 使用的 class 是否都有 CSS 定义
- 样式层叠是否被旧规则压住

## 质量门禁

`make test` + `make vet` + `make frontend-check` 构成合并前的最低门禁。
CI 额外执行:

- `gofmt` 检查
- `go vet`
- `go test -race`
- `CGO_ENABLED=0` 构建
- 离线模拟 + 报告非空
- MySQL 契约测试

## 已知限制

- 受限沙箱无法绑定端口, 因此 `httptest` / `miniredis` 相关用例在沙箱内会失败;
  这是环境限制, 在普通开发机与 GitHub Actions 上正常。
- 语音首块/打断延迟目前是命令行实测, 浏览器端打断延迟仍待真机数据。
